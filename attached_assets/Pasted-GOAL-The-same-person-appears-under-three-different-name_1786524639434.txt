today by two JSON files that must agree. Replace both with one table, editable
on the Organization page.

THE TRAP - do not get this wrong
"PAWAN KUMAR" is TWO different people:
  - In rate list Sheet2 head column (alongside SANDEEP JI, ANANT SINGH), it is
    a STATE HEAD. HR canonical name: "Pawan Kumar Sharma". His seven CRM team
    members all list "Pawan Kumar Sharma" as Reporting Manager. 206 rows.
  - In the CRM roster member column, "PAWAN KUMAR" is a TEAM MEMBER under
    Nasir Hussain Khan. A different person.
Resolve by ROLE, never by name alone. A prior merge of this name left
Rs 259.4 Cr reading as zero prior-year.

TABLE
person_registry
  employee_code        from HR. PRIMARY key where present and <= 4 digits.
  canonical_name       from HR
  alias_primary        rate-list / sale-register form, e.g. "SANDEEP JI"
  alias_secondary      CRM form, e.g. "Sandeep Dadheech"
  alias_sheet          working-sheet form where it differs
  reporting_manager    from HR - the TRUE five-tier line
  state_head           the ROLLUP head - from the CRM roster
  is_state_head        boolean
  is_person            boolean

reporting_manager and state_head are DIFFERENT FIELDS and both must be stored.
Riyas V reports to SANOJ M. and rolls up to Biju C.O. Storing one loses the
other. Measured against HR, 16 CRM members listed under Biju C.O actually
report to five different managers - that is the five-tier hierarchy, not an
error.

NON-PERSON HEADS
OTHER, PROJECT, GOVT, JJM, GEM are head values in the primary chain but are
not people. Store them with is_person = false so head resolution succeeds
without inventing an employee. "OTHER" is a real bucket (811 rows) with its
own state-head file - treat it as a head, not as unassigned.

EMPLOYEE CODE IS NOT ALWAYS USABLE
Of 179 active HR members: 117 have a plausible code (<= 4 digits), 37 other
long numeric, 14 round-number placeholders, 7 contain "+" characters, 4 look
like mobile numbers. Real values include 78900000000000000000 and 289696+35486.
Where the code fails plausibility, key on
normSecKey(name) + ":" + normSecKey(reporting_manager) and flag the row for HR
correction. Do not silently accept a bad code as an identity.

Employee code 5900000000000 is held by TWO active people - Jijo (Manjeri,
under SANOJ M.) and Basit Ahmad Pala (Anantnag, under Nasir Hussain Khan).
Keep both. Code 940 is held by "Balamurugan .V" and "V. Balamurugan", both
Deactive - same person entered twice with the name reversed. Flag, do not
merge.
