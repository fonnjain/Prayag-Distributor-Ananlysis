## A. My unit_mismatch rule was wrong. It excludes Rs 7.05 Cr that is fine.

I asked you to flag a whole CODE when its implied MRP varied by more than
2% within August. I checked the August file row by row, and that rule is
far too blunt:

```
Flagged by the code-level rule   102 codes   7,204 rows   Rs 7,05,41,795
Rows within 5% of their code's
usual implied MRP                             7,046 rows   Rs 6,87,07,930
Rows that look like a real unit
problem (ratio >2x or <0.5x)                     27 rows   Rs     4,84,368
```

Examples:

| Code | Rows | Rows at the usual implied MRP | Outlier rows |
|---|---|---|---|
| PW 11 | 266 | 265 (970) | 1 |
| 701 | 275 | 274 (1,450) | 1 |
| 144 | 343 | 342 (216) | 1 |
| 120-WS | 274 | 272 (132) | 2 (one at 0.04) |

So one bad row was knocking out a whole code. That is 36% of August value
removed from discount, for no good reason.

**A1. REPLACE the rule with a row-level test:**

```
ratio = row implied MRP / effective catalogue MRP

between 0.5 and 2.0    keep: priced from the catalogue as normal
outside 0.5 to 2.0     UNIT_MISMATCH: exclude this ROW only, count it
```

Also flag a row as PRICE_OUTLIER when it is more than 5% away from its
code's modal implied MRP. Keep it priced, but show it in the controls.

**A2.** Report the new numbers:
- unit_mismatch rows, codes and value (expect about 27 rows, about
  Rs 4.8 L)
- discount_mrp coverage as a percentage of value, before and after this
  change

**A3.** Record in PRAYAG_OPERATING_RULES.md, section 12: "Unit and outlier
tests are row-level. One bad row never excludes a code."
