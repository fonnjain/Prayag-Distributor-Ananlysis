## Notes

- A3 is the deliverable. If the parser's dry-run figures match the six independent
  numbers above, the file is good and loading it becomes a decision rather than a
  risk. If they differ, we have a parser question to settle first.
- D2 matters more than it looks. Nineteen days of August presented as a whole
  month would be a new instance of the partial-period problem, on a page that
  currently shows nothing at all.
- C2 is the question underneath all of this. If PS Code 3 SKU data and order
  booking are the same measure counted differently, then Apr-Jul is not missing —
  it is in a different table under a different name. If they are genuinely
  different measures, Apr-Jul order booking has no source and that is for Prayag.
- Nothing should be loaded off the back of this reply. The point is to know
  whether the file is sound and what loading it would move.
