GOAL
Two new tabs on SKU Deep Dive, beside Overview / Review / Push / Trends /
Discounts / Timing / Movement.

Both compare LIKE MONTHS against the prior fiscal year - never a rolling
window, never unequal periods. Both respect the existing scope selectors
(distributor / head / state / distributor filter) exactly as the other tabs do.

============================================================
TAB 1 - VOLUME DECLINE
============================================================
SKUs whose absolute piece count has fallen, ranked by the size of the fall.

  Group by segment, then by item code within it.
  Metric: qty this period minus qty in the same months last year.
  Sort: largest absolute piece decline first. Absolute pieces, not percentage
  - a code down 40,000 pieces matters more than one down 80% of 300.

Columns per row:
  segment · item code · item name
  qty now · qty last year · piece change · % change
  net now · net last year · net change
  distinct customers now vs last year
  gross contribution per piece, where cost data exists

Show a segment subtotal line, and rank segments by their own total piece
decline so the worst segment reads first.

Include a code with zero purchases this period but purchases last year - that
is the most complete form of decline. Mark it "stopped".

============================================================
TAB 2 - PRICE SHRINKERS
============================================================
SKUs where pieces went UP but real value went DOWN, because the MRP rise
outran the value growth.

THE CALCULATION - use MRP, matching Red Alert B1
  Hold last year's basket fixed and re-price it:

    qtyGrowth%     = (qty now / qty last year - 1) x 100
    valueGrowth%   = (net now / net last year - 1) x 100
    mrpIndex       = SUM(qty last year x MRP now)
                     / SUM(qty last year x MRP then)
    mrpIncrease%   = (mrpIndex - 1) x 100
    realGrowth%    = valueGrowth% - mrpIncrease%

  Both MRP figures from mrp_history, which is effective-dated - "MRP then"
  means the price in force during the prior period, not today's.

  Resolve ambiguous codes on (item_code, segment). 56 codes exist in two
  segments at different prices - CNS-15 is Rs 860 in PTMT and Rs 1,020 in CP.
  A code-only lookup uses the wrong price.

QUALIFYING CONDITION
  qtyGrowth% > 0  AND  realGrowth% < 0

  Pieces rose and real value still fell. Rank by realGrowth% ascending -
  worst first.

Columns:
  segment · item code · item name
  qty now · qty last year · qty growth %
  net now · net last year · value growth %
  MRP then · MRP now · MRP increase %
  REAL GROWTH % - the headline, worst first
  realised price now vs then, as a diagnostic

SHOW THE REALISED-PRICE FIGURE ALONGSIDE
Compute the realised-price index too (net / qty, both periods) and show it
beside the MRP figure. The two together separate the cause:

  real decline on BOTH bases       -> genuine, the SKU is losing value
  real decline on MRP basis only   -> discount leakage; volume held, price
                                      gave way

That distinction changes who acts. Volume is a sales problem; discount is a
terms problem.

NO MRP DATA
817 register codes have no MRP at all - whole families including PTA-, CPCS-,
CPA- and PSS-. Those codes CANNOT appear on this tab. Show a count at the top:
"N codes excluded - no MRP on record" with the list available on expand.
Never treat a missing MRP as zero or as no change.
