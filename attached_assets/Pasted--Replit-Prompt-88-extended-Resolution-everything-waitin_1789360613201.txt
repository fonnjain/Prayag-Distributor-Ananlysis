# Replit Prompt 88 (extended) — Resolution: everything waiting on someone

**Date:** 14 September 2026
**Supersedes:** the earlier Prompt 88.
**Scope:** A is the register. B is enforcement. C is the page. D loads the
entries. E is the export.

**Standing rule:** every figure states which database or source it came from.

---

## What changed in this version

The register now covers **everything waiting on someone**, not only data that
must be blocked.

**Two types, one register, and they behave differently:**

**HOLD** — blocks a figure. PTMT margin cannot be shown until answered. The
system enforces it.

**PENDING** — blocks nothing. The 34 DIST# codes need confirming; nothing on
screen is wrong. Somebody owes an answer.

Roughly twenty-five items currently live across a dozen documents. Nobody can see
them in one place, and the note to Prayag is reassembled by hand each time.

## Section A — the register

```
Code change. A general register of open items, with types.

TABLE: resolution_item

  id
  type                HOLD or PENDING
  title               short, human
  category            data quality, master data, access, infrastructure,
                      commercial
  fiscal_year, month or month range     nullable - not every item has one
  scope_product       nullable
  scope_measure       WHICH measures are blocked. HOLD only. Never a whole
                      month by default
  reason              plain language
  evidence            the figures, so nobody re-derives them
  value_at_stake      rupees, where it exists. Nullable
  raised_on, raised_by
  owner               Prayag, Deepak J, IT, internal, or a named person
  status              open, answered, resolved, accepted-as-is
  resolved_on, resolved_by, resolution_note
  blocks_api          HOLD only

RULES

1. Only HOLD enforces. PENDING is a record, never a block.
2. MEASURE-SCOPED. A hold blocks named measures, never a whole month.
3. Evidence goes in the record. The next reader must not repeat the
   investigation.
4. Resolved items are RETAINED, never deleted.
5. accepted-as-is is a real outcome, not a failure.
6. DAYS OPEN is derived and shown. Some of these predate this month.
```

## Section B — enforcement, HOLD only

```
B1. CALCULATION. A blocked measure returns UNAVAILABLE - never zero, never
    silently omitted.

    A held month must not be quietly dropped from an average. Twelve-month
    margin covering eight months says eight.

B2. DISPLAY. Blank-grey with the hold title and a link to Resolution.
    Aggregates containing a held period state their coverage.

B3. API - THE IMPORTANT ONE. An external consumer requesting a held
    measure receives an EXPLICIT STRUCTURED EXCLUSION naming the hold,
    scope and reason.

    Not silence. Not zero. Not an empty array. A consumer receiving nothing
    may substitute zero, which is worse than an error.

    Print the response shape before building.

B4. WHAT IS NOT BLOCKED. For PTMT Jan-Apr 2026: sales value, quantity,
    order booking, discount and realisation all work normally. Only margin,
    gross contribution and cost are held.

B5. Print every surface consuming margin and confirm each honours the
    register - SKU contribution, volume decline, push list, K4,
    recommendations, Red Alert C4.
```

## Section C — the page

```
Under Settings.

  - OPEN items first, sorted by days open descending
  - a toggle to sort by value at stake instead
  - HOLD and PENDING visually distinct - a hold is blocking something now
  - filter by owner, category and type
  - each row: title, type, owner, days open, value at stake, status
  - expanding shows reason, evidence, scope and what unblocks it
  - any blocked figure elsewhere links to its hold

  Admin can add, edit and resolve. Everyone else reads.

  NOT an alert feed. This is a register of known, accepted gaps - a
  different thing from something going wrong now.
```

## Notes

- **The type split is what makes this work.** A hold blocking a figure and a
  question owing an answer are different things; one register, two behaviours.
- **Days open creates pressure a document never will.** The PTMT question predates
  this session by weeks, and nothing currently shows that.
- **Value at stake changes the conversation.** ₹9.64 Cr unpriced, ₹6.52 Cr
  uncoded, ₹1.17 Cr on WCT. Sorted by rupees waiting, the priority order looks
  quite different from sorted by date.
- **Section E is the practical payoff.** The Prayag note becomes an export rather
  than a writing task, and nothing gets forgotten between rounds.
