## Section A — the ledger. First, unchanged.

```
Code change. A durable ingest ledger for the primary monthly register. Show
the diff before applying.

The secondary dashboard already has this - durable ingest-run records with
append-only row revisions. The primary register keeps only the latest
baseline and frozen anchor, with rows-read and rows-written in runtime
results. That is why the 492 August rows cannot be reconstructed, and why
a nine-row baseline change took a separate investigation to explain.

WRITE IT INSIDE THE SAME PER-MONTH TRANSACTION as replaceOpenMonths, so a
ledger record cannot commit while its data replacement rolls back.

Record per run, per affected month:
  - run identity, scheduler or operator, timestamps
  - fiscal year and month label
  - source rows read, rows written
  - before and after row counts and values
  - rows ADDED, REMOVED, CHANGED as counts
  - before and after fingerprints
  - source spreadsheet id, tab, content hash
  - outcome: replaced, frozen-skipped, frozen-anchored,
    aborted-short-read, rejected-shrink, failed

MAKE EVERY SHRINK VISIBLE. Any nonzero reduction in rows or value is
recorded and surfaced regardless of size. SHORT_READ_TOLERANCE at 0.98
stays as a catastrophic-read guard only - never as approval for normal
shrinkage.

ALSO RECORD REJECTIONS. August's shrink was read, parsed with zero skipped
rows, and refused - and left no durable trace. A rejected read is as
important as an accepted one.

DO NOT change sync scope, the freeze clock, openMonthLabels,
SHORT_READ_TOLERANCE, or the replacement mechanism. This is instrumentation;
behaviour stays identical.

AFTER APPLYING, print the schema, a dry-run sample record, and confirm no
sync behaviour changed. Then publish and push.
```

Code change. Two things, both about the same invariant. Show the diff first.

1. PERSISTED FROZEN STATE OVERRIDES THE CALCULATED CLOCK

   A month that has been frozen must never reopen, regardless of how the
   freeze clock is later changed. Make persisted frozen or anchored state

   the rejected source count and reason. It should not look identical to a

   Print every month across all fiscal years that is calendar-frozen with

DO NOT unfreeze anything, adopt any source, or run the drift detector -
that writes records and belongs to Section C.

AFTER APPLYING, print August's register_month_state before and after, the
