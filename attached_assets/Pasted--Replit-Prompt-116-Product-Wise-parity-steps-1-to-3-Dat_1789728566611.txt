## Section C — Step 2: the MRP adapter

```
Code change. This is what restores secondary discount.

Product-Wise has Discount %, Discount Amount, Basic Order Value and
Product Code - but no observed mrp or gross_amount.

Primary discount already resolves sale_line.code against mrp_history for
closed periods and mrp_synced for the open FY, with the not-offered
exclusion. product_code is the same join key.

C1. SELECT effective MRP by product_code and transaction month.
C2. APPLY the same not-offered and missing-MRP rules. A month with no
    effective price means the product was not offered - exclude, count,
    state.
C3. RETAIN the Product-Wise discount percentage and basic ex-GST value.
C4. DERIVE gross only where the discount is valid and the denominator is
    non-zero.

C5. LABEL IT DERIVED, NEVER OBSERVED. This is the audit's key condition. A
    reconstructed gross is not the CRM's gross column and must not be
    presented as one.

C6. EXPOSE the controls: row counts, missing-MRP counts, excluded codes,
    and coverage as a percentage of value.
```
