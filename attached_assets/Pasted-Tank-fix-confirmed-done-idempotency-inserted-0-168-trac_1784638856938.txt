DO NOT "FIX" IT BY ADDING AMOUNT TO THE IDENTITY KEY

That recreates the original bug in reverse - every rate edit becomes a new
permanent row. Amount is a MUTABLE ATTRIBUTE, not part of identity. The correct
behaviour is what versionedSyncLines was supposed to do all along:

  when an incoming sheet row matches an existing current row on identity
  (invoice, code, colour, qty, month), and the amount differs, supersede the old
  row and make the incoming one current - one current row per identity, always.

22600950 shows a path where that isn't happening. Find why the old row wasn't
superseded when the new one arrived:

    ran, so they crossed?
  - does the supersession only fire when the incoming row is NEW (insert path)
    and skip when a matching current already exists (the 250 "already existed"
    slots from check 1a)?
  That second one is the likely culprit - check 1a said 250 replacements
  "already existed as current from earlier runs." If two replacements for the
  same identity both got inserted across different runs, both are current and
  neither supersedes the other.
