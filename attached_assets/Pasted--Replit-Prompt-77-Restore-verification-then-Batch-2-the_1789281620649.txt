## Notes

- **Section A is not optional housekeeping.** Every publish this month has been
  verified against the live API. Losing that check means the next one rests on
  "the build succeeded", which is a weaker claim and would not have caught several
  things it did catch.
- **C1 is the whole of Batch 3.** If targets are set per group, this is safe and
  mechanical. If they are allocated, member totals move and someone has to decide
  whether that is acceptable — which is a conversation, not a diff.
- **C4 is where this touches people.** A member crossing an alert threshold because
  their target was regrouped would receive an alert caused by a taxonomy change.
  That needs to be known in advance.
