============================================================

for ALL 3,316 rows, and writes the real classification into entity_type as

PART 2 - TYPE ERRORS IN THE SAME FILE
============================================================

A type check of api-server surfaces about 30 real errors (excluding
dependency-resolution noise). Eleven of them - a third of the total - are in
routes/customerMaster.ts, all from the recent work:

  line 220  TS7053  implicit any: expression of type string|number|symbol
                    used to index type {}
  line 221  TS2538  symbol cannot be used as an index type
  line 222  TS2538  same
  line 224  TS2339  Property 'company' does not exist on type '{}'
  line 311  TS7053  same pattern as 220
  line 312  TS2538
  line 314  TS2538  (twice)
  line 614  TS2538  (twice)
  line 619  TS2345  string|number|symbol not assignable to string

These are all the same root cause: an object typed as {} being indexed with
an untyped key. They pass at runtime until a key of an unexpected shape
arrives, which is exactly what a CSV load can produce.

Give those objects real types rather than casting to any. If a row shape is
genuinely dynamic, type it as Record<string, string> and validate the keys
you actually read.

Do NOT fix type errors in other files in this task - extraGroups.ts,
primaryStateAchievement.ts and skuPushList.ts have their own and should be
separate.
