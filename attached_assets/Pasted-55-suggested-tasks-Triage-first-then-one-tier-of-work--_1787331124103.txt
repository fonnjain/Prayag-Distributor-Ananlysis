#237 - THE BIGGEST GAP
A column-detection failure in the secondary register can silently delete
months of order data.

secondary_register_line has NO wipe protection. secondary_sku_line has two
guards - a runtime abort-before-delete and the CI canary - and the register
table, carrying the same volume through a different loader, has neither.

  a. Extend assertRegisterWipeGuard to the same proportional rules already
     used on secondary_sku_line: per-month rows >= 0.60x prior like-month,
     total >= 0.70x, distinct distributors >= 0.70x.
  b. It must ABORT before any delete, inside the transaction. Not warn.
  c. A column-detection failure producing zero parsed rows must abort, not
     delete-then-insert-nothing.
  d. Extend the CI canary to cover secondary_register_line, and have it STATE
     WHICH DATABASE it checked - the canary has only ever run against dev.

#281 - MAKE THE REFUSAL VISIBLE

failure with no explanation and has no way to know it was a guard doing its
job.

counts, the ratio, and which month failed.
