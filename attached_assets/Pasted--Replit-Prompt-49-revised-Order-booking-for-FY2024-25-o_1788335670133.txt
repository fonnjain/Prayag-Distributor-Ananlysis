## Two corrections that changed the scope

**The grain block was mine and it was wrong.** PSCode 3 Sub Total is line-level.
All 123,326 FY2026-27 rows carry non-null `net_amount`, and SORD-155203 proves it
— ₹1,378 and ₹1,225 across two lines summing to the ₹2,603.04 order total.

**"Order ID was dropped everywhere" was misleading.** It was dropped **on write**,
not lost. `loadOrderFile` reads the Segment Wise workbooks daily and returns
**52,515 distinct Order IDs for FY2025-26** and **49,080 for FY2024-25**. The
references are in the source and are being read right now. Only the two database
loaders failed to map the column.

That reframes the historical years entirely.

## The two formats are near-identical

| | PSCode 3 (Apr–Jul 2026) | Segment Wise (FY2024-25, FY2025-26) |
|---|---|---|
| Columns | Sr.No, Date, Retailer Id, Retailer, **Order ID**, Segment, Cat. No., Qty, MRP, Order Value, Distributor, Discount, Sub Total, Order Total | **identical** |
| Team member | from the filename | from a column in the sheet |

One structural difference. Same `v1` layout, same present fields, same absent
fields — no order status, no CP code, no GST.

**A parser built for Apr–Jul 2026 handles FY2024-25 and FY2025-26 with one
change.**

## Why the earlier objections do not apply to those two years

| Objection | FY2024-25 / FY2025-26 |
|---|---|
| No Order ID in the database | Irrelevant — read from source, as `loadOrderFile` already does |
| No Order ID at source | **False.** 49,080 and 52,515 distinct |
| No safe full-FY replace path | Concerns `secondary_register_line`, untouched here. This is a fresh insert into an empty table |
| 26.8% / 28.0% null net | That is FY2021-22 and FY2022-23. These two are **100% populated** |

Every objection applies to the three oldest years and none to these two.

**FY2021-22 through FY2023-24 stay out** — no Order ID column at source, and
FY2023-24's workbook covers April 2023 only.

## Notes

- **B3 is the one that could quietly ruin the comparison.** Both legacy workbooks
  carry rows outside their own fiscal year — FY2025-26 spans 23 months. If the
  load trusts the workbook boundary rather than the row date, the prior-year
  figure is inflated and every year-on-year number is wrong in the same
  direction.
- **B2 is worth thinking about rather than answering reflexively.** Segment Wise
  and PSCode 3 are the same CRM sharing one SORD counter. Treating them as one
  legacy era would surface a genuine duplicate if the same order appeared in
  both; treating them as two would hide it. The safer choice is probably one.
- **B8 is new.** Roughly 1.09 million rows into a table that has never held one.
  Worth a moment on indexing and export before, not after.

## Still out of scope, and why

FY2021-22, FY2022-23 and FY2023-24 have no Order ID column at source. FY2023-24's
workbook covers April 2023 only — 16,274 rows, ₹10.53 crore, against a full-year
primary register of ₹349 crore. Those three cannot be order-level from any source
we have.

## Unrelated findings worth keeping

The documented re-ingest path is unsafe: the config says move an entry back to
`registers` and rebuild, but the loader inserts by `line_uid` with conflict
avoidance and no full-FY replace route exists. Re-running could append rows while
leaving stale ones. Nothing in this prompt goes near it.

The two existing loaders disagree on the same source — FY2023-24 SKU has 26 more
rows than the register, FY2024-25 one fewer. Gate 2 never compared them.
