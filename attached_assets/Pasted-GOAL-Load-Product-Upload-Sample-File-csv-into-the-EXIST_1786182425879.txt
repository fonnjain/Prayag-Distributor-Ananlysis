NATURAL KEY - this is the important part
The key is (Product Code, UPPER(TRIM(Feature Name))), NOT Product Code alone.
Feature Name holds the COLOUR or length variant, and price varies by colour.
Example: code 4012 "ECO Orissa Pan" is White Rs 1,960, Ivory Rs 2,350,
Blue/Green/Pink Rs 2,450. Those are correct prices, not conflicts.

- Uppercase Feature Name before keying. The file mixes WHITE (341 rows) and
  White (158), IVORY (318) and Ivory (124).
- Blank Feature Name is valid - 5,003 rows have no variant. Key it as ''.
- One cell holds "IVORY,WHITE" (code 453). Split it into two rows.

Expected: 6,108 rows collapse to 6,055 distinct keys.

REGISTER JOIN NORMALISATION
The sale register writes codes differently from this master. Implement a
resolver used in THIS ORDER - exact first, always:

  1. Exact match on Product Code.
  2. If the register code is "P" followed by all digits, strip the P.
     Verified: P6818->6818, P6806, P6875, P6812, P6802 all resolve.
  3. If the register code ends in a colour letter after an optional space or
     hyphen (B, G, P, J, W), strip that suffix to get the base code and treat
     the suffix as the colour. Verified: 7118-B->7118, 4011B, 4011G, 4019-P,
     4051-B, 4303 J all resolve.
  4. Collapse internal whitespace. Verified: register Q724MB -> master Q724 MB.

Step 1 MUST run before steps 2 and 3. Codes 130-B, 141-E, 121-E, 129-C are
legitimate register codes that match exactly; stripping their suffix would
break them.
