## Structure

**One file per salesperson**, 181 files, 34 MB, single `Sheet1` each.

| Row | Content |
|---|---|
| 1–2 | two-row header band |
| 3+ | data |
| last | **`Total:` row — must be excluded** |

Columns:

```
A Sr.No.   B Date       C Retailer Id   D Retailer     E Order ID
F Segment  G Cat. No.   H Qty           I MRP          J Order Value
K Distributor          L Discount (%)   M Sub Total    N Order Total
```

**Two arithmetic identities, both verified exactly:**

```
Sub Total   = Order Value x (1 - Discount/100)     line level
Order Total = sum of Sub Total for that Order ID   order level, on the last line only
```

**`Sub Total` is the line-level NET.** `Order Total` is an order footer and must never be summed across lines.

## Three cautions before loading

**1 — The `Total:` row.** Every file ends with one, in column A, with the total in column M. Parsed as data it adds a phantom row equal to the whole file — Prasun would read ₹36.69 L instead of ₹18.35 L, exactly double.

**2 — 115 of 181 files disagree with their own `Total:` row** by ₹4 to ₹9. Rounding in the sheet's own footer, not a parse error, but it means the footer cannot be used as a checksum.

**3 — 16 pairs of files share an identical total**, including `RAVINDER PURI` / `Ravindera` at ₹52.25 L and `SASHIKANT PRASAD` / `SASIKUMAR A` at ₹50.14 L. Either genuine duplicates under different spellings, or two people with coincidentally equal totals. **Resolve before loading, or the same business counts twice.**
