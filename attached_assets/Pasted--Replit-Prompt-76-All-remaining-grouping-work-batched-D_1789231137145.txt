# Replit Prompt 76 — All remaining grouping work, batched

**Date:** 12 September 2026
**Follows:** the Prompt 74 sweep.
**Scope:** Four batches. Batch 1 runs as one change. Batches 2, 3 and 4 must be
separate.

**Standing rule:** every figure states which database or source it came from.

---

## Can these all run together? No — and here is why

**Batch 1 is display-only.** Labels and groupings change, totals do not. Safe as
one change.

**Batches 2, 3 and 4 each move figures**, and they must be isolated so the effect
of each is attributable. Running them together means a number moves and nobody
can say which change did it — the problem that has cost this project days more
than once.

**Batch 2 and Batch 4 also touch the same AI builders.** Running them together
would make the denominator fix and the taxonomy move indistinguishable.

Sequence: **1 → 2 → 3 → 4**. Each published and verified before the next starts.

## Not in scope, deliberately

**Scheme eligibility.** `scheme_item_group` is a separate 22-value vocabulary.
It must not be remapped without an approved item-code crosswalk, and a category
change must never silently alter who qualifies for a slab.

**Secondary segment surfaces.** `secondary_sku_line` and `secondary_register_line`
group by `segment_canon`, which is a different axis rather than an outdated
version of this one. The sweep flagged them for confirmation, not migration.

**Source-owned groupings** — Overview Product Mix, Momentum Order Groups, Pending
Orders factory group, Alerts CRM Category Name. Each comes from a source system
with its own vocabulary. Moving them is a separate decision about whether the app
re-classifies source data or reports it as given.

## Notes

- **Batch 1 first because it is free.** Three surfaces, no totals move, and it
  makes the app visibly consistent for the common case.
- **Batch 3's Section A is the important half.** A1 decides whether this is a
  relabelling or a reallocation, and those are very different changes. If member
  totals move, targets are being redistributed and that needs a business decision,
  not a code change.
- **A4 is the one to read carefully.** If members cross alert thresholds because
  their target was regrouped, the alert engine will fire on a taxonomy change.
  That must be known before, not discovered after.
- **Batch 4 after Batch 2**, always. Both touch AI builders, and running them
  together makes the denominator fix and the taxonomy move indistinguishable.
