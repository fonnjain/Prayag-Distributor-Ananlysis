## Notes

- Sections A, B and C are the reconciliation proper. D is the stop condition. F
  is the one that tells you whether this file matters much at all against a
  register frozen at July.
- Section H is worth reading first when the reply comes back. If the website is
  already carrying the 01 September master, there is nothing to load and the
  whole exercise becomes a confirmation. If it is not, the app is currently
  serving prices the manufacturer has superseded, and that is a different
  conversation.
- Section I asks for the raw payload because nobody on our side has seen it. The
  client code declares more fields than the API may actually return, and treats
  the missing ones as review gaps rather than errors, so an incomplete feed
  degrades quietly rather than failing. I4 in particular: the file has 150
  colour-specific prices and the API contract appears to have no field to carry
  a price per colour, only variant names.
- If the agent cannot reach the live API, the honest answer is "cannot reach it".
  A reconciliation run against the local cache would compare the cache to the
  file and tell you nothing about the authority, while looking like it had.
- Nothing here unblocks the PTMT BOM conflict. That is a factory cost dispute,
  not an MRP one. A September MRP against a disputed January-to-March cost makes
  the margin gap wider, not narrower.
- Hold the three excluded rows marked Invalid Input for Prayag to confirm. They
  carry no usable code.
