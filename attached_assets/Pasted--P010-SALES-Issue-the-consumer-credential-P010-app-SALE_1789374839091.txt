## Why proceed

```
Variance    −Rs 10,80,007.94  on  Rs 1,35,23,20,560.20      0.08%
```

The consumer uses **item-level sales values and margin percentages**, not the aggregate. A variance of 0.08% spread across roughly 11,825 item-months cannot move an individual product's margin percentage enough to change which side of a pricing floor it falls.

It still matters as a reconciliation failure, and **P003 remains open and should be answered.** But it is not a reason to withhold data whose use is unaffected by it.

---

## Conditions

**The variance travels with the data.** Every response's `coverage` block must state it, so the consumer can display it and no user has to ask how complete a figure is:

```json
"reconciliation": {
  "fy": "2026-27",
  "control":  135340056814,
  "actual":   135232056020,
  "variance": -108000794,
  "variance_pct": -0.0008,
  "status": "unreconciled",
  "reference": "P003"
}
```

Include it whether or not the period reconciles. A consumer that sees the field only when something is wrong will not know what its absence means.

**Scope the key narrowly.** `external_read` only, the two item endpoints only. Not an admin account, not `X-Admin-Secret`, not a `full_api` or verification key.

**Make it revocable and attributable.** One key for this consumer alone, so it can be revoked without affecting anything else, and so its usage is identifiable in logs.

**State the rate limit and page size** you have issued it under — 60 requests per minute and 500 rows per page, unless that has changed.
